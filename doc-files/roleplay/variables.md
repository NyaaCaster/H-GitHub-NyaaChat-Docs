# 角色变量

角色变量是在对话过程中**动态变化的数值**——比如好感度、生命值（HP）、任务进度、金币数量等等。它们让角色不只是会说固定的话，而是能感知到"状态的变化"。

> ⚠️ 变量由**角色卡自带的脚本**读写，所以需要先在顶部工具栏点开[「扩展」](../extensions/)（拼图图标），启用 [「脚本运行器」](../extensions/script-runner) 插件。插件没启用时脚本不会运行，变量也就不会产生、不会更新。

## 变量是什么

变量是一组**键值对**——一个名字对应一个值；值可以是数字、文本，也可以是一层层嵌套的结构。例如一张宿舍题材的卡片可能有这样的状态：

```
世界:
  当前日期: 2022.09.01
舍友列表:
  苏婷:
    好感度: 20
```

和世界书、正则不同，变量不是你在界面里手写的规则，而是**由角色卡自带的脚本算出来的**：脚本决定有哪些变量、初始值是多少、什么时候变化。NyaaChat 只负责把值保存下来，并按下面的方式交给模型。

> 一句话：**变量跟着卡片来**。卡片里没有脚本，就没有变量。

> 💡 这套玩法来自 SillyTavern 生态里的卡片脚本（例如 MVU）。NyaaChat 通过「脚本运行器」插件运行这类卡片脚本，因此可以支持带变量的卡片。

## 三个作用域

变量可以存在三个不同的地方，可以理解为"这份数据算多大范围"：

| 作用域 | 存在哪里 | 适合放什么 |
|--------|----------|------------|
| **楼层（message）** | 附在某一条消息上 | 某一条消息对应的状态快照 |
| **会话（chat）** | 跟随当前这段对话 | 这段对话里累积下来的数据 |
| **全局（global）** | 保存在浏览器本地 | 跨角色、跨对话都想保留的数据 |

- 切换对话，会话变量就跟着换；全局变量对所有对话、所有角色都是同一份。
- 同名变量可以同时存在于不同作用域，互不影响（读取时靠宏名区分，见下一节）。
- 具体写在哪一层、什么时候写，由**卡片脚本**决定，不需要你来安排。

## 在提示词里读取变量：6 个宏

在世界书规则的内容里，可以用下面 6 个宏把变量的当前值交给模型：

| 宏 | 作用域 | 输出 |
|----|--------|------|
| <code v-pre>{{get_message_variable::路径}}</code> | 楼层 | 一行 JSON |
| <code v-pre>{{format_message_variable::路径}}</code> | 楼层 | 缩进好的 YAML 块 |
| <code v-pre>{{get_chat_variable::路径}}</code> | 会话 | 一行 JSON |
| <code v-pre>{{format_chat_variable::路径}}</code> | 会话 | 缩进好的 YAML 块 |
| <code v-pre>{{get_global_variable::路径}}</code> | 全局 | 一行 JSON |
| <code v-pre>{{format_global_variable::路径}}</code> | 全局 | 缩进好的 YAML 块 |

- **路径**指向要取的那个值，分隔符用 `/` 或 `.` 都行：<code v-pre>{{get_message_variable::舍友列表/苏婷/好感度}}</code> 与 <code v-pre>{{get_message_variable::舍友列表.苏婷.好感度}}</code> 等价。
- 省略路径（写成 <code v-pre>{{get_chat_variable}}</code>）表示取该作用域下的**全部**变量。
- `get_` 系列输出紧凑，适合塞进一句话里；`format_` 系列输出 YAML，适合成块展示。
- 取不到值时（路径写错、或该作用域还没有变量），宏会替换成空。

> 这 6 个宏是**提示词侧**的宏，写在世界书规则的内容里。正则规则只做文本查找替换、不会执行脚本，所以不能用正则来读写变量。

## 典型用法：把状态交给模型

MVU 这类卡片的常见做法是：卡片脚本把状态写进变量（通常放在 `stat_data` 这一组里），卡片再用一条世界书规则把整组状态渲染成模型好读的 YAML：

```text
<status_current_variables>
{{format_message_variable::stat_data}}
```

（示例只画出开头一行；真实规则里，这一行宏会被一对自定义标记包住，末尾是它对应的闭合标签。）

这样模型每一轮都能看到最新的状态，回复时就能像"知道"当前日期、舍友好感度一样自然。具体有哪些字段、长什么样，完全由卡片决定——NyaaChat 只负责把变量值填进宏的位置。

## 初始值从哪里来

- **初始值由卡片决定**：卡片脚本会在合适的时机建立初始值。不少卡片会配合一条世界书条目存放初始数据（作者常用 `[initvar]` 之类的名字标注，并把它设为不启用）。
- **NyaaChat 不提供变量的编辑界面**：变量不是在这里手填的，而是卡片脚本算出来的；想改变量，只能改卡片本身。

## 如何查看与重置

**查看**

目前没有内置的变量查看界面。可行的方式：

1. **看卡片自己的展示**——不少卡片会把状态写进 AI 的回复文本里，具体形式由卡片决定。
2. **直接在对话里问它**——用上面的宏把值交给模型，然后问"现在的状态是什么"。
3. **偏技术向**：在浏览器的开发者工具里查看 NyaaChat 保存在本地的数据。

**重置**

变量跟着"它存在哪里"走：

| 想清掉 | 做法 |
|--------|------|
| 楼层变量 | 删除附有它的那条消息 |
| 会话变量 | 开始一段新对话，或删除这段对话 |
| 全局变量 | 清除浏览器为 NyaaChat 保存的站点数据 |

> 变量存在对话里，不在卡片上。因此**只重新导入卡片**既不会恢复初始值，也不会清掉已有对话里的变量；想重新开始，请新开一段对话。

## 和世界书、正则的分工

| 能力 | 负责什么 | 与变量的关系 |
|------|----------|--------------|
| **脚本运行器（插件）** | 运行角色卡自带的 JS 脚本 | ✅ 变量的产生与更新都在这里 |
| **世界书** | 按关键词或常驻把内容插入提示词 | 可以用上面 6 个宏**读取**变量 |
| **正则** | 查找并替换文本 | ❌ 不会执行脚本，不能读写变量 |

> 💡 排查：卡片里明明有变量、对话中却读不到时，先确认「脚本运行器」插件是否已启用，以及卡片是否确实自带脚本。
