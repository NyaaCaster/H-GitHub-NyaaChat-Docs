# 破甲模块（Answerer·Flagalac）

> 主动响应式破甲，后发而先斩之剑。

NyaaChat 内置的**破甲模块**用于应对 Gemini 系列模型在创作场景下的拒答与道歉：它在请求里注入一套角色化的会话约定，让模型按设定继续输出；若模型仍然道歉或拒答，产品会**自动更换破甲方案重新请求**。

## 适用范围

| 项 | 说明 |
|------|------|
| 生效平台 | **仅 QinyAPI** 提供的 Gemini 模型；其他供应商、其他模型族无效 |
| 可用模型 | `gemini-2.5-pro`、`gemini-3.1-pro-preview`、`gemini-3.7-flash` |
| 当前测试范围 | 开发阶段**只在默认组**落地测试；其他分组下同名、异名的模型均无法保证效果 |

> ⚠️ 破甲模块属**进阶功能**，只在需要时开启。日常问答与普通角色扮演无需开启。

## 如何开启

1. 点击主界面**右上角的 🔥 火焰图标（Bypass）**，打开破甲设置弹窗。
2. 在**目标**下拉中选择与当前对话模型匹配的一项。

| 目标 | 对应模型 |
|------|----------|
| `无` | 不启用本模块，不注入任何绕过内容（默认） |
| `gemini2.5pro & 3.1pro` | `gemini-2.5-pro`、`gemini-3.1-pro-preview` |
| `gemini3.7flash` | `gemini-3.7-flash` |

3. 在下方按需勾选该目标提供的设定条目（名称与效果见下一节）。

> 💡 **目标必须与模型匹配**：目标选错时模块仍会正常发请求，但不会命中对应模型的拦截机制，效果无法保证。

> 💡 **「流式输出」会被自动调整**：切换破甲模式时，模块会自动变更「流式输出」设定。**变更后请不要手动修改**，否则会导致破甲失败。

## 可开关的设定条目

每个目标都提供一组可**单独开关**的条目，按需勾选即可（不再是一刀切）。下表只说明"勾上之后的效果"，不涉及内部实现。

### 目标 `gemini2.5pro & 3.1pro`

| 条目 | 效果 |
|------|------|
| **认知复写** | 重新定位系统指令，让后续内容被当作"规则"而不是"请求" |
| **执行者代理** | 用叙事方式接管身份，替代直接的能力声明 |
| **根源接触** | 把对话情境与输出任务衔接起来，减少直接拒绝 |
| **破限加强** | 追加一段长篇前置设定（世界观式前言 + 召唤契约），面向长篇创作场景；**默认关闭**，可随时开启 |
| **魔术回路** | 正文经由函数工具参数返回，再由产品侧回收为可见正文 |
| **阵地制作** | 载荷以转义序列下发，响应侧再解码回可读正文 |
| **痕迹抹除** | 从请求中剥离思考痕迹，避免历史里的旧痕迹被回传 |

### 目标 `gemini3.7flash`

| 条目 | 效果 |
|------|------|
| **认知复写** | 同目标一：重新定位系统指令，让内容被当作规则 |
| **执行者代理** | 用两张模型卡把「执行者」与「叙述者」的身份隔开 |
| **干涉咏唱** | 以一段开场声明替代拒绝式回应 |
| **破限加强** | 同目标一：追加长篇前置设定；**默认关闭** |
| **魔术回路** | 同目标一：正文经函数工具参数返回并被回收 |
| **阵地制作** | 同目标一：载荷转义下发、响应解码 |
| **痕迹抹除** | 剥离思考痕迹，并清掉来源形态的控制标记 |

## 运行时的表现

- **自动重试**：模型若仍然道歉或拒答，NyaaChat 会自动换一种破甲方案重发（最多尝试数次）。
- **等待期间**：气泡会显示当前状态（正在重试 / 已停止重试），不会再出现空白气泡。
- **全部失败**：显示「已停止重试」，该轮没有正文。
- **上游异常**：显示状态码并提示服务恢复后重发，不会自动重试。
- **设置随行**：破甲设置（含「破限加强」）会随**设置导出/导入**完整保留。
